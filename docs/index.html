axpublish

디자이너의 Figma 파일을 AI가 읽고, 디자인 토큰을 바인딩하고, 반응형 웹 코드로 퍼블리싱하는 오픈 파이프라인입니다.

💡
한 줄 요약 Figma 링크를 주면 AI가 Figma에 토큰을 직접 바인딩하고, 반응형 HTML/CSS 코드까지 만들어 로컬에 내려줍니다.

왜 만들었나

웹 디자인을 AI가 퍼블리싱하려면, AI가 디자인을 읽을 수 있는 구조가 먼저 필요합니다. Figma의 하드코딩 파일은 AI가 패턴을 인식하기 어렵습니다.

axpublish는 Seed Design 토큰 시스템을 기반으로 Figma 파일을 정규화하고, AI가 일관된 규칙으로 코드를 생성할 수 있도록 만든 파이프라인입니다.

기존 방식axpublish

AI가 색상을 제각각 해석시맨틱 토큰으로 일관 처리
반응형 규칙 없음, 매번 수동 정의clamp() fluid 타이포그래피 — 뷰포트에 따라 자동 스케일
Primary 컬러 바꾸면 전체 수동 수정hex 하나만 바꾸면 Figma + 코드 전체 반영
버튼을 화면마다 다시 만듦컴포넌트 라이브러리를 한 번 만들고 재사용

작동 방식

axpublish는 두 가지 아웃풋을 만들어냅니다. Figma 파일 자체를 토큰으로 정리하고, 동시에 코드도 생성합니다. 단, Code Generation은 Figma가 완전히 확정된 이후에만 시작합니다.

6-Phase 워크플로우

axpublish-orchestrator.md에 각 Phase의 행동 지침이 정의되어 있습니다. AI는 이 문서를 읽고 순서대로 실행합니다.

Phase 0

Discovery & Figma 세팅

브랜드 컬러 수집 → HSL 스케일 생성 → theme.css 출력 → Figma Variable 49개 생성 → 레이어 바인딩 → 인터랙션 상태 시각화 → 충돌 검증 → 디자이너 확정 게이트

Phase 1

타이포그래피 바인딩

Figma 텍스트 레이어 전체 추출 → Seed Design 16레벨 토큰 매핑 (오차 ±2px 자동, 초과 시 디자이너에게 질문)

Phase 2

반응형 구조 분석

Auto-layout → CSS Flex/Grid 변환. 섹션별 Mobile/Tablet/Desktop 처리 방식 확정. 규칙 밖 섹션은 디자이너에게 PAUSE 보고.

Phase 3

전역 컴포넌트 라이브러리

재사용 요소 스캔 → Figma Component 생성(MCP Write) + Code 파일 생성 동시 진행. 버튼/GNB/인풋/모달 등 한 번만 만들고 이후 재사용.

Phase 4–5

화면별 조립 & 로컬 QA

한 화면씩 완성 → 디자이너 로컬 프리뷰(npx serve .) → 승인 → 다음 화면. 전체 일괄 빌드 금지.

Phase 6

UI / Interaction QA

전체 화면 완료 후 hover/GNB/모달/스크롤 인터랙션 전수 검수. 통과 후 GitHub 업로드는 디자이너 자율.

Figma MCP Write

axpublish의 핵심입니다. Figma를 읽기만 하는 게 아니라, 직접 Variable을 생성하고 레이어에 바인딩합니다.

인터랙션 상태 시각화

바인딩 완료 후 axpublish / Interaction States 페이지에 버튼 상태 매트릭스를 자동으로 그립니다. Primary 컬러가 바뀌면 Variable 바인딩으로 자동 반영됩니다.

// 버튼 상태 매트릭스
Default  → Primary/Normal            배경 + Static/White 텍스트
Hover    → Primary/Strong            배경
Pressed  → Primary/Heavy             배경
Disabled → Interaction/Disable       배경 + Interaction/Inactive 텍스트

컴포넌트 라이브러리 (Phase 3)

재사용 가능한 UI 요소를 딱 한 번 만듭니다. Figma에는 Component로 등록하고, 코드에는 재사용 파일로 생성합니다. 이후 화면 조립 시 라이브러리에서 가져다 씁니다.

Figma Component 생성 → Code 파일 생성 (동시)

⚠️ 재사용 기준: Figma 전체 스캔 후 2회 이상 등장하는 요소만 컴포넌트화. 1회만 등장하는 섹션(Hero 등)은 해당 page.tsx에 인라인으로 작성.

Button.tsx 예시

// src/components/atoms/Button.tsx
type ButtonProps = {
  label: string
  variant?: 'primary' | 'secondary' | 'ghost'
  size?: 'sm' | 'md' | 'lg'
  disabled?: boolean
  onClick?: () => void
}

export default function Button({ label, variant = 'primary', size = 'md', disabled, onClick }: ButtonProps) {
  const sizes = { sm: 'px-4 h-9 text-sm', tb: 'px-5 h-12 text-sm', lg: 'px-6 h-14 text-base' }
  const variants = {
    primary:   'bg-primary-normal text-static-white hover:bg-primary-strong active:bg-primary-heavy',
    secondary: 'bg-secondary-normal text-static-white hover:bg-secondary-strong',
    ghost:     'bg-transparent border border-line-solid-normal text-label-normal hover:bg-fill-normal',
  }
  return (
    <button
      onClick={onClick} disabled={disabled}
      className={`inline-flex items-center justify-center rounded-md font-semibold
        transition-colors duration-150 disabled:cursor-not-allowed
        disabled:bg-interaction-disable disabled:text-interaction-inactive
        ${sizes[size]} ${variants[variant]}`}
    >{label}</button>
  )
}

토큰 시스템

tokens.css는 전역 기본값, theme.css는 프로젝트별 Primary/Secondary override입니다.

컬러 스케일 생성

# Primary hex 하나로 13단계 자동 생성
node generate-theme.js \
  --primary "#0066FF" \
  --secondary "#FF7300" \
  --output ./theme.css

# 출력 예시
--color-primary-heavy:   #0054D1;  /* pressed */
--color-primary-strong:  #005EEB;  /* hover */
--color-primary-normal:  #0066FF;  /* default (입력값) */
--color-primary-inverse: #3385FF;  /* 역색 배경 위 */
--color-primary-tint:    #EBF2FF;  /* 뱃지 배경 등 */

텍스트 컬러 6단계

토큰용도불투명도
--color-label-strong가장 강한 강조, 주요 제목100%
--color-label-normal기본 본문, 일반 제목100%
--color-label-neutral보조 텍스트88%
--color-label-alternative더 흐린 보조61%
--color-label-assistive힌트, 플레이스홀더28%
--color-label-disable비활성 텍스트16%
