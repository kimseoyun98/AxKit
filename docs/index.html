axpublish

디자이너의 Figma 파일을 AI가 읽고, 디자인 토큰을 바인딩하고, 반응형 웹 코드로 퍼블리싱하는 오픈 파이프라인입니다.

💡
한 줄 요약 Figma 링크를 주면 AI가 Figma에 토큰을 직접 바인딩하고, 반응형 HTML/CSS 코드까지 만들어 로컬에 내려줍니다.

왜 만들었나

웹 디자인을 AI가 퍼블리싱하려면, AI가 디자인을 읽을 수 있는 구조가 먼저 필요합니다. Figma의 하드코딩 파일은 AI가 패턴을 인식하기 어렵습니다.

axpublish는 Seed Design 토큰 시스템을 기반으로 Figma 파일을 정규화하고, AI가 일관된 규칙으로 코드를 생성할 수 있도록 만든 파이프라인입니다.

기존 방식axpublish
하드코딩 Figma (#1A2B3C 직접 입력)Semantic Variable로 바인딩된 Figma
AI가 색상을 제각각 해석시맨틱 토큰으로 일관 처리
반응형 규칙 없음, 매번 수동 정의clamp() fluid 타이포그래피 — 뷰포트에 따라 자동 스케일
Primary 컬러 바꾸면 전체 수동 수정hex 하나만 바꾸면 Figma + 코드 전체 반영
버튼을 화면마다 다시 만듦컴포넌트 라이브러리를 한 번 만들고 재사용

퍼블리싱 팀 & 사용자 여정

axpublish는 역할이 나뉜 5명의 AI 직원과 디자이너(당신)가 협업합니다. 각 직원 카드와 사용자 여정을 가로 슬라이드로 확인해보세요.

🔍 SCOUT → 🎨 BINDER → 📐 FLEX → ⏸ 디자이너 검수 → 🔧 BUILDER → 🏗️ ASSEMBLER → ⏸ 최종 검수
🔍
SCOUT
디자인 분석가
Figma MCP Read

디자이너의 Figma 파일 전체를 스캔하여 화면 목록, 컴포넌트, 색상/폰트 사용 현황, Variables 적용 여부를 분석해 팀에 브리핑합니다.

🎨
BINDER
토큰 연결 담당
Figma MCP Write

Figma 내부에 axpublish / Seed Variable Collection(59개 토큰, Light/Dark)을 생성하고 하드코딩된 색상을 시맨틱 토큰으로 1:1 자동 바인딩합니다.

📐
FLEX
반응형 초안 생성
responsive-rules.md

Desktop 프레임을 읽어 responsive-rules.md 기반으로 Figma 내에 Tablet + Mobile 초안 프레임을 자동 생성합니다. 디자이너 검수가 필요합니다.

🔧
BUILDER
컴포넌트 코드 제작
React + Tailwind v4

확정된 3-뷰포인트 디자인을 읽어 재사용 가능한 컴포넌트 단위로 코드를 생성합니다. Seed CSS 토큰만 사용하며 임의 하드코딩을 절대 자제합니다.

🏗️
ASSEMBLER
페이지 조립 담당
Page Assembly

BUILDER가 생성한 컴포넌트를 레이아웃에 맞춰 순차 조립합니다. 화면별 로컬 프리뷰 및 디자이너 검수를 거쳐 다음 화면 조립으로 진행합니다.

Typography

t1 ~ t16 — 화면별 고정값 (static responsive)

t9~t16: seed-tokens.css에서 화면별 고정값으로 override
✦ t15·t16은 Seed 공식 스케일 확장 (56px, 72px)

t5 — Body (16px). 이 텍스트는 clamp()로 화면에 따라 자동 조절됩니다. 별도 미디어쿼리 없이도 가독성이 유지됩니다.

t2 — Caption (12px). 보조 설명, 타임스탬프.

CSS 사용 패턴

/* ── 반응형 Display 타이포 패턴 (권장) ── */
.hero-title {
  font-size: var(--seed-font-size-t12);   /* Mobile  32px */
}
@media (min-width: 768px) {
  .hero-title { font-size: var(--seed-font-size-t14); } /* Tablet  48px */
}
@media (min-width: 1280px) {
  .hero-title { font-size: var(--seed-font-size-t15); } /* Desktop 56px ✦ */
}

/* ── 기본 바디 / 레이블 ── */
.body-text {
  font-size: var(--seed-font-size-t5);       /* 16px */
  line-height: var(--seed-line-height-t5);
  color: var(--seed-color-fg-neutral);
}

.label {
  font-size: var(--seed-font-size-t4);       /* 14px */
  font-weight: var(--seed-font-weight-bold);
}

.caption {
  font-size: var(--seed-font-size-t2);       /* 12px */
  color: var(--seed-color-fg-neutral-muted);
}

작동 방식

axpublish는 두 가지 아웃풋을 만들어냅니다. Figma 파일 자체를 토큰으로 정리하고, 동시에 코드를 생성합니다. 단, Code Generation은 Figma가 완전히 확정된 이후에만 시작합니다.

STEP 1

📁 Raw Figma ➔ MCP 연결

SCOUT이 디자인 파일 전체 스캔. 화면·컴포넌트·색상·폰트 현황 파악.

STEP 2

🛠️ MCP Write & 바인딩

BINDER가 Variable 59개 생성, 레이어 전체 1:1 바인딩 및 상태 시각화.

STEP 3

🔒 Figma 확정 게이트

디자이너의 최종 "OK" 신호 이후에만 코드 생성 진입. 불일치 원천 차단.

STEP 4

💻 Code Gen & QA 완료 🎉

BUILDER 컴포넌트 생성 ➔ ASSEMBLER 순차 조립 ➔ 인터랙션 QA 후 완공.

Figma MCP Write — 내부 동작

axpublish의 핵심입니다. AI(BINDER)가 MCP를 통해 Figma 파일 내부에 직접 Seed Variable Collection을 생성하고 모든 레이어에 바인딩합니다.

STEP 1

Variable Collection 생성 (59개)

axpublish / Seed 컬렉션을 Light 및 Dark 2개 모드로 자동 생성합니다. Primitive(palette/)는 원본 Hex 스케일로 다루고, Semantic(fg/, bg-*/, stroke/) 토큰이 이를 Alias 참조합니다.

❖ Figma Variable 패널 구조 (BINDER가 자동 생성하는 트리)
axpublish / Seed (Modes: Light / Dark) ├── 🪨 palette/ (Primitive: 레이어 직접 지정 X) │ ├── carrot-100 ~ 900 (Hex 값: 브랜드 덮어쓰기) │ ├── gray-00 ~ 1000 (Hex 값: 중성색 스케일) │ └── status (green/red/yellow/blue-700) └── 🎯 Semantic 토큰 (레이어 직접 지정 O / palette 참조) ├── fg / neutral → alias: palette/gray-1000 ├── fg / brand → alias: palette/carrot-600 ├── bg-layer / default → alias: palette/gray-00 ├── bg-brand / solid → alias: palette/carrot-600 ├── bg-neutral / inverted → alias: palette/gray-900 ├── bg-status / positive-solid → alias: palette/green-700 └── stroke / neutral-subtle → rgba(0,0,0,0.08)
그룹개수변수 (Seed CSS 대응)
palette24개carrot-100~900 (브랜드, override) + gray-00~1000 + status 4색
fg11개neutral / neutral-muted / neutral-subtle / neutral-inverted / brand / disabled / placeholder / positive / critical / warning / informative
bg-layer4개default / fill / floating / basement
bg-brand4개solid / solid-pressed / weak / weak-pressed
bg-neutral4개inverted / solid / weak / disabled
bg-status5개positive-solid / critical-solid / warning-solid / informative-solid / overlay
stroke7개neutral-subtle / neutral-muted / neutral-solid / neutral-contrast / brand-solid / critical-solid / focus-ring

※ palette는 Primitive — Semantic이 alias로 참조하며, 컴포넌트에는 Semantic 토큰만 바인딩합니다.

STEP 2

레이어 자동 바인딩 (Hex ➔ Seed Variable)

Figma 전체 레이어를 순회하며 하드코딩된 Hex 색상을 가장 적합한 Seed Semantic Variable로 자동 전환합니다. 

// BINDER의 1:1 자동 바인딩 규칙
  텍스트 레이어 Fill
    기본 진한 텍스트 (#121212, #171719)   → fg/neutral         (--seed-color-fg-neutral)
    보조 설명 텍스트 (#424242, #616161) → fg/neutral-muted   (--seed-color-fg-neutral-muted)
    브랜드 강조 텍스트 (#0066FF)          → fg/brand           (--seed-color-fg-brand)

  Frame / Component 배경 Fill
    화면 전체 / 기본 카드 배경           → bg-layer/default   (--seed-color-bg-layer-default)
    회색/회색조 섹션 배경                → bg-layer/fill      (--seed-color-bg-layer-fill)
    Primary 버튼 배경                    → bg-brand/solid     (--seed-color-bg-brand-solid)

  Stroke (테두리·구분선)
    연한 카드 테두리 / 카드 구분선       → stroke/neutral-subtle (--seed-color-stroke-neutral-subtle)
    강한 외각 테두리                      → stroke/neutral-solid  (--seed-color-stroke-neutral-solid)

  상태 (Status) 메시지 및 뱃지
    성공 / 완료 (#388E3C 계열)           → fg/positive        (--seed-color-fg-positive)
    에러 / Danger (#C62828 계열)         → fg/critical        (--seed-color-fg-critical)
    경고 / Caution (#F57F17 계열)        → fg/warning         (--seed-color-fg-warning)
⚠️
미매핑 또는 기존 Style 충돌 시 PAUSE
Seed 토큰에 존재하지 않는 특수 색상이나 외부 라이브러리 Style이 감지되면 작업을 일시 중지하고 디자이너의 선택을 요청합니다.
STEP 3

인터랙션 상태 시각화 (State Matrix)

바인딩 완료 후 Figma 파일 내 axpublish / Interaction States 페이지를 신설하여 UI 주요 요소(버튼, 인풋 등)의 Default / Hover / Pressed / Disabled 상태 매트릭스를 자동 생성합니다. 

// BINDER가 시각화하는 버튼 상태 매트릭스
  ┌─────────────┬─────────────┬─────────────┬─────────────┐
  │   Default   │    Hover    │   Pressed   │  Disabled   │
  ├─────────────┼─────────────┼─────────────┼─────────────┤
  │ bg-brand/   │ bg-brand/   │ bg-brand/   │ bg-neutral/ │
  │ solid       │ solid-press │ solid-press │ disabled    │
  │ 텍스트:     │ 텍스트:     │ 텍스트:     │ 텍스트:     │
  │ fg/neutral- │ fg/neutral- │ fg/neutral- │ fg/disabled │
  │ inverted    │ inverted    │ inverted    │             │
  └─────────────┴─────────────┴─────────────┴─────────────┘

  // 시각화 컴포넌트 목록
  Primary 버튼:   bg-brand/solid → solid-pressed
  Secondary 버튼: bg-neutral/inverted → bg-neutral/solid
  Ghost 버튼:     배경 투명, 테두리 stroke/neutral-solid
  Input:          Default / Hover / Focus (stroke/brand-solid) / Error (stroke/critical-solid) / Disabled
  Link:           Default (fg/brand) / Hover / Visited
STEP 4

디자이너 확정 게이트 🔒

Figma 상의 Variable 바인딩 및 인터랙션 시각화 상태를 디자이너가 직접 검수한 후 "OK" 또는 "다음 진행"을 승인해야만 코드 생성 단계(Phase 4 BUILDER)로 진입합니다.

🔒
Code Generation은 디자이너 승인 이후에만 수행
승인 전에 임의로 코드를 조합하거나 빌드하지 않음으로써 Figma 디자인 ↔ Code 구현 간 불일치를 원천 차단합니다.

6-Phase 워크플로우

axpublish-orchestrator.md에 각 Phase의 행동 지침이 정의되어 있습니다. AI는 이 문서를 읽고 순서대로 실행합니다.

Phase 0

Discovery & Figma 세팅

브랜드 컬러 수집 → generate-seed-brand.js 실행 ➔ Figma axpublish / Seed Variable 59개 생성 ➔ 전체 레이어 1:1 바인딩 ➔ 인터랙션 상태 시각화 ➔ 미매핑/충돌 검증 ➔ 디자이너 확정 게이트 🔒

Phase 1

타이포그래피 바인딩

Figma 텍스트 레이어 전체 추출 ➔ Seed Design 16레벨 토큰(--seed-font-size-t1~t16) 매핑. 뷰포트별 스태틱 3단계 브레이크포인트 적용.

Phase 2

반응형 구조 분석 (FLEX)

Figma Auto-layout → CSS Flex/Grid 변환. responsive-rules.md 기반으로 Tablet & Mobile 초안 자동 생성. 규칙 밖 예외 시 디자이너에게 PAUSE 보고.

Phase 3

전역 컴포넌트 라이브러리 (BUILDER)

2회 이상 사용되는 요소 스캔 ➔ Figma Component 등록 + Code 파일 생성(React + Tailwind v4) 동시 진행. 버튼/GNB/인풋/모달 등 컴포넌트 모듈화.

Phase 4–5

화면별 조립 & 로컬 QA (ASSEMBLER)

한 화면씩 순차 조립 ➔ 디자이너 로컬 프리뷰(npx serve .) ➔ 뷰포트 검수 및 승인 ➔ 다음 화면 조립 진행. 일괄 빌드 절대 금지.

Phase 6

UI / Interaction QA

전체 화면 반응형 인터랙션(Hover/GNB/모달/스크롤) 전수 검토 ➔ 검수 완료 후 GitHub 저장소 업로드는 디자이너 자율 진행.

컴포넌트 라이브러리 (Seed Components)

Seed Design 토큰(fg/*, bg-*/*, stroke/*)을 바인딩하여 Figma Component 등록과 동시에 생성되는 12가지 핵심 재사용 UI 컴포넌트 카탈로그입니다.

1. Button

Atom

Primary, Secondary, Ghost, Danger 4개 타입 / Default, Hover, Pressed, Disabled 4개 상태.

bg-brand/solid, bg-brand/solid-pressed, fg/neutral-inverted

2. Input & TextField

Atom

Default, Focus(Focus-ring), Error(Critical), Disabled 5가지 상태 지원.

stroke/neutral-muted, stroke/focus-ring, stroke/critical-solid

3. Badge & Tag

Atom

Success, Warning, Critical, Neutral, Brand 5가지 시맨틱 색상 라벨.

bg-status/positive-solid, bg-status/critical-solid, fg/brand

4. GNB (Navigation)

Molecule

Desktop 전체 메뉴 노출 ➔ Mobile 햄버거 슬라이드 Drawer로 자동 변형 특수 컴포넌트.

bg-layer/default, stroke/neutral-subtle, fg/neutral

5. Modal & Dialog

Molecule

Desktop 중앙 팝업 ➔ Mobile 하단 슬라이드업 Bottom Sheet로 자동 변형 특수 컴포넌트.

bg-layer/floating, bg-status/overlay, stroke/neutral-subtle

6. Card & Grid Item

Molecule

Desktop 3열 고정 ➔ Tablet 2열 ➔ Mobile 1열 세로 스택 자동 변형 컴포넌트.

bg-layer/floating, stroke/neutral-subtle, fg/neutral-muted
